# Security
**Implemented:** prepared statements only · output escaping (`e()`) everywhere · strict CSP (no inline script/style) + nosniff, frame-deny, referrer policy · CSRF token on every POST (incl. JSON via header) · session cookie HttpOnly/SameSite=Lax/Secure(prod), id regenerated on login, server-side revocable sessions, device list · `password_hash` (bcrypt default, rehash on login) · login throttling (5 fails/15 min per email, 20 per IP) with identical errors for unknown accounts · reset/verify tokens stored hashed, single-use, expiring · reset/register responses don't enumerate accounts · open-redirect-safe post-login redirect · backend permission checks + group scoping on every route (no reliance on hidden buttons) · server-computed payment amounts · callback secret path, IP allowlist option, size limit, strict parsing · idempotency keys, unique constraints, row locks · immutable ledger/audit via triggers · CSV formula-injection neutralised · secrets only in environment (shown masked) · audit trail for sensitive actions and exports.

**Permission matrix** (`src/Core/Permissions.php`): chairperson (all group admin, plans, roles, waivers, settings, audit; can approve expenses/reversals) · treasurer (payments, manual entries, reversals, reconciliation, expenses create/approve/pay, reports) · secretary (members, announcements, expense proposals, reports) · auditor (read-only finance, audit, reports) · member (own data only). Dual control: reversal requester ≠ approver; expense approver ≠ requester, two approvers above the group's threshold. Platform super admin: users/groups/integrations/jobs/backups, **no** group finance access.

**Not implemented (be aware):** MFA, Google sign-in, email-OTP step-up for sensitive actions, file uploads (logos/expense receipts), per-IP rate limiting beyond login, account lockout notifications, encrypted-at-rest fields, WAF. `mail()`-based verification email is unreliable. Run a dependency-free review: there are no third-party PHP/JS dependencies to audit.
**Before production:** HTTPS + HSTS, set `APP_ENV=production`, strong `MPESA_CALLBACK_SECRET`, restrict callback IPs, DB user with least privilege (needs TRIGGER only for migrations), off-box backups, penetration test, and a Kenya Data Protection Act assessment (ODPC registration, privacy notice, retention policy, DPIA).
