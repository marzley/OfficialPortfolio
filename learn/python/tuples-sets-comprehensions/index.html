Tuples, sets and comprehensions

You know lists. Python has other collections for other jobs, and a short way to build them called comprehensions.

Choosing the right collection

TypeExampleOrdered?Changeable?Duplicates?Use for
list[1, 2, 2]YesYesYesMost sequences
tuple(1, 2, 2)YesNoYesFixed records, coordinates
set{1, 2}NoYesNoUnique items, fast "is it in?"
dict{"a": 1}Yes (insertion)YesKeys uniqueLook-ups by key

Tuples: fixed records

Tuples can't be changed (location[0] = 0 is an error), which makes them safe for data that shouldn't change, and usable as dictionary keys.

Common mistakes

MistakeFix
t = (5) is just the number 5One-item tuple needs a comma: (5,)
{} creates an empty dict, not a setset() for an empty set
Expecting sets to keep orderSets are unordered; sort if needed
Putting lists in sets or as dict keysUse tuples (immutable) instead
Huge, unreadable comprehensionsUse a normal loop

Think about it: Why would you store GPS coordinates as a tuple rather than a list?Show answer

A location is a fixed record (latitude, longitude) that shouldn't change by accident; tuples are immutable, slightly lighter, and can be used as dictionary keys or set members (e.g. a set of visited locations), which lists can't.
