01 · Architecture overview

The system is deliberately simple to host: a pre-built static website (HTML generated by Python), a PHP 8 back-end for everything that needs data (portal, payments, learning hub API), one MySQL database, and a few external services. It runs on ordinary cPanel shared hosting: no Node server, no framework, no build step on the server.

Section 04

Build pipeline (static pages)

python3 tools/build_pages.py turns the homepage and content files into every page of the site. Run it after any content change, then commit the generated files.

  1. minify_assets(): esbuild minifies css/home.css and js/home.js into .min files (set ESBUILD=/path/to/esbuild; falls back to a copy).
  2. Sections: sections_of() splits index.html and content/sections.html by <section class="section" id="…">.
  3. Pages: each entry in PAGES (slug, title, description, list of section ids) becomes slug.html via make_page(): a copy of the homepage shell with its own title, description, canonical, Open Graph, JSON-LD and body. The first h2 becomes the page's only h1; #anchor links are rewritten to the page that now owns that section (HOME_OF).
  4. Blog and case studies: read_posts() parses the header comment (title, seo_title, description, date, tag, image, image_alt, live), counts reading time, and build_post() writes each post with BlogPosting schema, breadcrumbs and related posts. fit_title() keeps titles ≤ 60 characters.
  5. Special pages: build_kiswahili() (translated strings, lang="sw") and build_404() (noindex, <base href="/">).
  6. write_sitemap(): all pages, posts (real dates), learning hub pages and all 190 lesson URLs.
  7. subset_icons(): scans every HTML/JS file for fa-* classes and builds a small Font Awesome CSS + woff2 subset (fontTools).
  8. inline_css(): inlines the critical CSS into root pages (faster first paint).
  9. learn_seo(): writes Course JSON-LD and a crawlable list of every lesson into learn/index.html from data/learn-seed.json.
  10. version_assets(): adds ?v=<sha1> to scripts/styles in root pages, the portal, the learning hub and the runner (and stamps engines.js's hash), so a new upload is never mixed with cached old files.
  11. sync_csp_hash(): recomputes the SHA-256 of the inline theme script and updates script-src in .htaccess.

Section 05

Front-end: the website

js/home.js is one IIFE of independent feature blocks, each guarded by a DOM lookup, so the same file runs on every page.

Features in js/home.js

  • Mobile menu, reveal-on-scroll (IntersectionObserver), reduced-motion support
  • Work list hover previews (GSAP), category filter chips
  • Count-up stats from data/stats.json
  • Quote calculator + printable PDF quote (js/print-page.js)
  • Deposit and care-plan payments → stkpush.php, polling status.php every 3 s
  • Booking form (.ics calendar file), call-back form
  • Website check UI → healthcheck.php
  • Referral links (?ref= stored in localStorage and sent with payments/leads)
  • Chat assistant: matcher over data/knowledge.json, then portal/chat.php (Claude) when enabled and unsure; unanswered questions go to chat-log.php
  • Accessibility panel (text size, contrast, motion, reading guide), theme toggle
  • Cookie consent → loads GA4 only after “Accept”; custom events
  • Lazy loading of Paystack and Google sign-in scripts

Forms and leads

Contact, booking, training and call-back forms POST to portal/lead.php, which saves a lead (Leads board), emails the team and replies to the visitor. If the portal isn't reachable, the form falls back to Formspree, then to WhatsApp/mailto.

Theme and styles

Colours are CSS custom properties on :root (--navy #0b1b35, --amber #ffb800, --amber-text #955a06, --line, --card …) redefined for [data-theme=dark]. js/theme-init.js runs before paint to apply the saved theme and accessibility classes (and adds html.js). Large screens use CSS zoom breakpoints; the portal and learning hub opt out.

Performance

Inlined critical CSS, responsive srcset WebP images, icon subset, self-hosted variable font, lazy third-party scripts, long-lived caching with content-hash versioning. Local Lighthouse score ≈ 97.

Section 07

Hosting: Apache, caching, CSP

.htaccess (root)

  • Canonical host: 301 to https://marzleytechsolutions.co.ke (http and www redirected).
  • Clean URLs: /pricing → pricing.html; index.html and trailing slashes redirected; legacy URLs mapped.
  • Security headers: nosniff, X-Frame-Options SAMEORIGIN, Referrer-Policy, Permissions-Policy, strict Content-Security-Policy.
  • Caching: HTML 0 s (always fresh); CSS/JS 1 month; images 6 months; fonts 1 year. Safe because every asset URL carries ?v=hash.
  • Compression: DEFLATE for text, JSON, SVG and application/wasm.

Section 08

Back-end: the PHP portal

portal/lib.php (~1,300 lines, 92 functions) is the shared core, included by every endpoint that defines MARZLEY_PORTAL.

Config

config() loads portal-config.php from one level above public_html (or PORTAL_CONFIG env var in tests) and merges defaults. Keys: db_dsn, db_user, db_pass, google_client_id, open_signup, admin_emails, storage_dir, backup_dir, backup_keep_days, offsite_backup, mail_from, site_url, smtp, sms, chat, business_name, kra_pin, etims, admin_idle_minutes, client_idle_minutes. M-Pesa keys live in mpesa-config.php: consumer_key, consumer_secret, shortcode, till_number, passkey, callback_url, callback_secret, environment.

Database

db() opens one PDO connection (exceptions on, emulation off). q($sql, $params) is the only query helper: always prepared statements. migrate() creates/updates tables in steps up to SCHEMA_VERSION = 7 (stored in settings), on MySQL and SQLite. learn_seed() syncs lessons when the seed version changes.

Responses and errors

out($data) sends JSON; fail($code, $msg) sends a JSON error. install_error_alerts() turns PHP errors into a friendly 500 and emails the admin (rate-limited).

Roles and permissions

Users: client or staff (admin if email is in admin_emails). Staff have permission sets (money, leads, projects, clients, support, courses, owner) checked by require_perm(); the admin UI hides tabs accordingly (TAB_PERM in app.js).

Section 11

Payments: M-Pesa and Paystack

M-Pesa STK push (Daraja)

  1. The browser sends phone + amount (+ purpose: deposit, care plan, invoice or video unlock) to stkpush.php, api.php?action=pay_invoice or learn.php?action=unlock.
  2. PHP gets an OAuth token (/oauth/v1/generate) using consumer_key/secret, builds the password base64(shortcode + passkey + timestamp) and calls /mpesa/stkpush/v1/processrequest (CustomerBuyGoodsOnline to Till 6095737). mpesa_base() picks sandbox or production.
  3. A row is saved with the CheckoutRequestID; the customer sees the PIN prompt.
  4. Safaricom POSTs the result to callback.php?secret=… (secret checked). The callback is logged outside public_html and settled: settle_payment() (invoice), settle_site_payment() (website deposit), settle_learn_payment() (video unlock). Each is idempotent.
  5. The browser polls status.php / payment_status / unlock_status every ~3 s and shows the receipt code.
  6. If a callback never arrives, the daily cron calls /mpesa/stkpushquery/v1/query and settles it.

Paystack (cards)

card_pay creates a transaction and returns the checkout URL; the client pays on Paystack and returns to portal/paystack.php?reference=…, which verifies with the secret key (settle_card()) and redirects to the portal.

Manual payments

Clients can report a Till payment with its receipt code (payment_claim); staff approve it (payment_decide) or record cash/bank payments (payment_record). eTIMS/KRA PIN can appear on invoices when configured.

Secrets: Daraja and Paystack keys only in mpesa-config.php / portal-config.php above public_html. Rotate them if they were ever shared. Only non-personal fields are returned by status.php.

12 · Authentication, sessions, referrals

  • Google: the GIS button returns an ID token; verify_google_token() checks it with Google's tokeninfo endpoint (audience = google_client_id, verified email).
  • Email codes: 6 digits, stored as sha256(client_id:code) (new accounts: new:email:code), 10-minute expiry, attempt limits, previous codes invalidated.
  • Open sign-up: with open_signup true, an unknown email creates a client (create_client_account()) with a client number and a permanent ref_code.
  • Sessions: cookie marzley_portal, path /portal/, HttpOnly, Secure, SameSite=Lax; idle timeouts for admins and clients; logout_all bumps a per-user session epoch so every device is signed out.
  • CSRF: random 32-byte token per session, required in X-CSRF-Token on every POST except sign-in actions.
  • Referrals: a code arrives via ?ref= (website) or sign-up; find_referrer() resolves it (client ref_code first); a referral moves enquired → signed up → project started → paid; referral_due() keeps it pending until client_work_done() (project live or admin “Work done”), then it's due (KSh 2,000) and the referrer is notified.

15 · Error helper

learn/help.js exposes MarzleyHelp.explain(lang, code, result) and lint(lang, code). The runner sends the full error in detail; explain() matches 100 ordered rules [langs, regex, title, why, fix, example] (with $1 capture substitution), finds the line with per-tool patterns (File "<exec>", line N, on line N, <source>:N:M, file.c:N:M, (line N) minus the script offset …), and renderHelp() in learn.js highlights the line (cm-err-line) and shows the card. lint() gives HTML/CSS tips (unclosed tags, missing alt, missing ; or }, British spellings, unitless numbers).

Change the video price

Per video in portal → Learning hub; default KSh 50 in learn.php.

Rotate payment keys

Generate new keys in the Daraja / Paystack dashboards, update the config files above public_html, test a KSh 1 payment. Never commit them.

Change brand colours

Edit the custom properties at the top of css/home.css (and portal/portal.css, learn/learn.css, which reuse them), rebuild, re-generate share images.
